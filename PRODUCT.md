# Product

## Platform

web

## Users

AP Computer Science Principles students and classmates use the portfolio in a browser to learn, practice, and demonstrate course concepts.

## Product Purpose

The portfolio presents coursework and interactive projects. This project teaches the parts of a desktop computer and the order of assembly through a snap-in activity while visibly demonstrating the AP CSP Create Performance Task concepts.

## Positioning

The PC assembly project connects a hands-on hardware lesson to inspectable pseudocode, JavaScript, and Python implementations of the same algorithm.

## Operating Context

Students open the project from the portfolio, arrange computer parts in an assembly workspace, receive immediate correctness feedback, and review copy-ready code-runner examples.

## Capabilities and Constraints

- The activity uses an ordered list of PC parts and records whether each placement attempt is correct.
- A correct part snaps into its destination only when it is also the next part in the assembly sequence.
- An incorrect part returns to the parts tray with a specific recovery message.
- Keyboard and pointer interaction must both work.
- The deliverable must include pseudocode, browser JavaScript, Python, and a short reflection.
- The named contributors are Adhvay Iyer, Rohan Chandra, Ishan Shrivastava, Ishan Jha, Ishan Khandelwal, and Vayun Shekhar. The source assignment describes three-person teams, so the final submission roster may need teacher confirmation.
- User roles and permission levels are not required for this single-player Hack #2 experience.

## Evidence on Hand

The assignment text supplied by the user defines the Hack #2 CPT requirements. No external performance claims, testimonials, or brand assets were supplied.

## Product Principles

- Teach by doing: every interaction should reinforce both hardware knowledge and an AP CSP concept.
- Make recovery immediate: an incorrect placement explains what happened and returns the part safely.
- Keep the algorithm inspectable: the visible activity and all three code versions should use the same data and logic.
- Make progress legible: the current assembly step, accuracy, and completed parts should always be clear.

## Accessibility & Inclusion

Every drag interaction must have a click or keyboard equivalent, status changes must be announced to assistive technology, and motion-reduction preferences must be respected.
