**Practice exam score shown in the reference: 63/66 (95.5%)**

Reviewing the 2018 practice exam gives me a useful way to organize my AP CSP preparation. A total score is a starting point, but the more useful question is whether I can explain why an answer works. I want to approach review by writing down my reasoning before checking a solution. If I cannot explain a step clearly, that step belongs on my study list even when I selected the correct answer. The results image below is preserved from the reference post and provides the example breakdown for this reflection.

## Test strengths and weaknesses

**My test strengths to build on:** The example shows 100% in Binary Numbers, Data Compression, Extracting Information from Data, and Developing Algorithms. Boolean Expressions, Conditionals, and Iteration also received full marks. These topics fit together: information has a representation, conditions guide decisions, and loops repeat the work. To check my understanding, I can translate one small algorithm between a written explanation, pseudocode, and Python. Getting the same output in all three forms would be more convincing than recognizing a familiar answer choice.

**My test weaknesses to address:** Using Programs with Data (50%), Identifying and Correcting Errors (75%), and Calling Procedures (80%) are the review priorities in the supplied breakdown. My practice should focus on the intermediate steps: what enters a procedure, which variable changes, and what value returns to the caller. A trace table will help me record those changes instead of trying to remember them mentally. I also want to test empty lists, repeated values, and boundary inputs, because a program can work for a typical example while failing on an overlooked case.

## Strengths and weaknesses in class

**My classroom strengths to develop:** Explaining code aloud is a practical way for me to check my understanding. During group work, I can contribute by choosing a small example, predicting its output, and walking through it with a teammate. Asking someone to challenge the prediction gives the discussion a clear purpose. Keeping a short note about what changed in my understanding would also make that discussion useful when I study later.

**My classroom weakness to work on:** I need a clearer standard for when work is finished. Producing an answer should lead to a second pass: checking assumptions, trying another input, and making the explanation easier to follow. For the next five class meetings, my plan is to reserve the final ten minutes for one of those checks. I will record the input I tested or the explanation I improved, so I can judge whether that time produced a useful result.

## My next steps

I will make three short practice sets covering data processing, debugging, and procedure calls. Each set will contain five unfamiliar problems. Before checking an answer, I will write a prediction and trace the relevant values. For every mistake, I will record the first incorrect step and solve a similar problem the following day. My target is four correct answers out of five in each set without hints. If I use AI to generate exercises, I will request questions first and explanations only after my attempt. At the end of the week, I will explain one corrected solution to a teammate and repeat a few questions without my notes.
